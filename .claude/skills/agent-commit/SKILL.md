# Commit unattended

Run these steps in order. Never prompt for confirmation, use `AskUserQuestion`, pass `--confirmed`, or create a pre-approval record. Missing authority holds the workflow with exit 75. Report the reason and leave the staged change and draft in place.

1. Run `bash .claude/skills/agent-commit/scripts/preflight.sh`. Create the initial commit through `commit` first. Stop for missing prerequisites or an operation in progress. The sibling `commit` and `review-commit-message` skills must come from the same installed package.
2. Read the diff, group one atomic change, and stage its paths by name. Never stage the whole tree.
3. Draft `COMMIT_AGENTMSG` using the message rules and identity printed by preflight. Explain why the change exists. Include `Assisted-by` before `Signed-off-by`.
4. Run the repository's `lint_commit_cmd`, which defaults to `mise run lint-commit-msg`. Fix findings before review.
5. Run `bash .claude/skills/agent-commit/scripts/review.sh`. Add `--amend` when replacing the current commit. The script runs the review and writes the stamp. Never supply a verdict yourself. Findings return 2, and reaching the configured finding bound returns 3. At the bound, use the redesign command below. Failed reviewer execution returns 4. Changed inputs return 5. Neither counts as a finding round.
6. Run `bash .claude/skills/agent-commit/scripts/commit.sh`, with `--amend` when reviewed that way. It runs the existing leak, lint, test, review, stamp, and confirmation gates. Only session pre-approval or the machine delegation check can permit it. Signing uses Git's configured SSH signer. A signing failure holds with exit 75. Restore signing before retrying.
7. Report the resulting commit and any groups still waiting. Don't push or rebase as part of this skill.

## Reviewer access

In Claude Code auto mode, an operator who agrees to the review can add `Bash(bash .claude/skills/agent-commit/scripts/review.sh *)` to `permissions.allow` in their settings. The trailing wildcard covers `--amend`, `--note`, and the bare command. The current script has no `--unblock` flag. Don't add a rule for one. An owner adds this permission, never the agent.

`review_cmd` chooses the reviewer. From Codex, configure one the session may start. These repository machines put this line in `~/.config/devtools/devtools.conf` so `agy` reviews in read-only plan mode:

```text
review_cmd = agy -p "$(cat)" --mode plan --add-dir "$DEVTOOLS_REVIEW_INPUTS" --print-timeout 900s
```

## Verification and configuration

The shared code verifies the resulting tree, message, parents, branch, and signature. If a hook changes the resulting commit, the script fails and retains the commit and review evidence for recovery. Never retry that failure without inspecting the state. It doesn't move a branch back automatically, since a hook may have pushed the commit already.

Repository behavior comes from `.agents/agent-skills.conf`, a declarative file of `key = value` lines. Supported keys are `lint_commit_cmd`, `required_hooks`, `hook_marker`, and `review_max_rounds`. Defaults require the executable `commit-msg`, `pre-commit`, and `post-commit` hooks with the `File generated by prek` marker and allow three finding rounds. The round bound accepts integers from 1 to 9. A successful commit clears its counter. At the bound, follow the redesign procedure below.

Authorities use the existing machine configuration under `~/.config/devtools/` or `DEVTOOLS_` environment variables: `review_cmd`, `review_model`, `review_effort`, and `delegation_check`. Repository configuration can't set these authorities. This skill reports through stdout and stderr and doesn't send messages to external services.

When the unattended finding bound returns exit 3, run `agentrepo review redesign KIND --reason TEXT` with `KIND` set to `commit`, `pr` or `squash`, then rewrite the draft from scratch. A rejected digest for the same subject refuses review before invoking the reviewer. Each active record permits one redesign. A bound after redesign requires inspection and refuses another start. Legacy records without rejected digests require inspection. The command leaves write authority and every other gate unchanged. A fresh description reset, where supported, remains separate from redesign.
